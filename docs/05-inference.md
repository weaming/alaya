# 05 · 计算与推理

本层回答：**在这套存储之上，如何把数据变成事实、把事实变成知识、把知识变成行动判断。** 它由四台引擎与一个完整认知循环组成。

## 1. 完整认知循环

一切推理围绕一个闭环，它是"科学方法"的存储化：

```
Observe ──▶ Record ──▶ Claim ──▶ Verify ──▶ Believe ──▶ Act ──▶ Observe
  │(事件入基岩)       (quad声称)   (证据+共识+     (scope内     (影响世界)
  │                                 世界内自洽)     world_fact)
  └──────────── 新观测/反例回到入口，闭环永不停 ───────────────┘
```

**关键认识**：这个环在时间中持续自我修正；系统记忆的不是"P 为真"，而是"P 在一段时间内、某 world、某 scope、由谁基于什么证据认定为真"。经得起时间考验的不是任何一条事实，而是**事实被产生与修正的机制**。

## 2. 引擎一：事实裁决（Truth Engine）

### 2.1 置信度传播

在论证图（03 §2.1）上做约束传播：

```
conf(claim) = Σ w_e · conf(evidence) · independence(evidence)
            − Σ w_a · conf(attack)     − Σ w_u · conf(undercut)
            + w_c · consensusSupport(claim, scope)
            + w_k · charterConsistency(claim, world)
```

- 证据独立性是关键权重：两条互相引用的证据不算"多重独立"；
- 观察者可信度本身是修正中的记忆（历史准确率），形成二阶可信度；
- 结果是一个**可解释的得分卡**（哪些证据、哪些反例、哪些共识、哪些自洽贡献了多少），供裁决记录留痕。

### 2.2 触发式裁决

裁决不必每条都跑：只对状态可能翻转的声称触发（新证据到达 / 出现 attack / 共识达成 / 宪章变更）。用惰性 + 事件驱动，控制计算成本。

### 2.3 反事实与可计算 oracle

在可计算世界（代码库、虚拟世界、仿真模型）内，裁决可以主动检验：

- 代码世界：把声称转成测试/类型检查/运行——**"线上事故 → 测试复现 → 修复 → 测试通过"是同一裁决机的实例**；
- 虚拟世界：用宪章规则推演剧情/设定冲突，输出 canon 冲突报告；
- real 世界：预测 → 等待新观测验证（predictive check）。

**符合判据（consilience）**：同时被观测支持、又被独立模型复现的声称置信度最高。

## 3. 引擎二：共识计算（Consensus Engine）

### 3.1 加权聚合

同一 scope 内出现冲突时：

```
支持度(claim, scope) = Σ participant.weight(scope, topic) · stance / Σ weight
weight = 角色权重(权威canon层更高) × 历史准确率(可修正) × 时效衰减
```

### 3.2 共识协议（状态机）

```
conflict ──协商──▶ majority ──强化──▶ unanimous ──外推──▶ cross_scope
   │                  │
   └──── agree-to-disagree（异议入 dissent，永不删除）
```

- 协议目标不是消灭分歧，而是**达成可行动的 scope 内结论，同时完整保留异议**；
- 共识对象可被超越（supersedes），旧共识是历史；
- **跨 scope 收敛**：个人→家庭→共同体→…逐层一致则向上迭代；物理法则 = 全 scope 收敛的极限。小范围共识是"可落地的客观性"。

### 3.3 社会性事实 vs 自然事实

- 社会性事实（约定/规范/canon/共同历史）：主要由共识机确立；
- 自然事实（天气/代码行为/物理事件）：主要由观测 + 可检验确立，共识只作佐证；
- 裁决记录必须标注事实类型，避免用错判据。

## 4. 引擎三：世界内推演（World Simulator）

- **世界状态**：每个 world 维护可计算的当前状态（real：事实快照；代码：代码库+依赖；虚构：canon 时间线与设定）；
- **推演**：给定状态 + 宪章规则 + 假设，生成"如果…则…"的事件（realm=virtual/fiction），写入基岩作为派生事件流，供裁决比对；
- **canon 冲突检测**：新设定与旧 canon 矛盾时，推演器产出冲突报告（哪条宪章、哪个旧设定、何种矛盾），交给共识机仲裁（作者声明 / 粉丝共识 / 平行世界分叉）；
- 世界状态本身是派生物（可从基岩重放重建）——**replayability** 是虚拟世界与代码世界的核心能力（代码世界即 CI/测试的意义）。

## 5. 引擎四：蒸馏与反思（Consolidation）

### 5.1 蒸馏管道

```
基岩事件批 → 蒸馏器(schema化抽取) → 候选声称(带证据) → 论证图待裁决
episodic 摘要 → 语义条目(semantic) → 核心画像(core, identity)
```

- 调度：任务/会话边界小蒸馏 + 定时深度蒸馏 + **空闲期 compute**（sleep-time reflection）；
- 蒸馏输出必须带证据引用与 importance/confidence 初值；
- **模型换代可重跑**：同一基岩用更好模型重蒸馏，记忆只变好不锁死。

### 5.2 遗忘调度（在派生层执行）

```
retention_score = importance × recency(最后命中) × scope活跃度
  高 ──▶ 自动注入槽
  中 ──▶ 仅可检索（不出现在 recall）
  低/过期 ──▶ archived（派生层删除/降冷，基岩永存）
```

### 5.3 核心画像（core）的特殊地位

core 是"人格同一性"的载体：用户价值观、铁律、长期偏好、跨年主线。它必须：

- 体积最小、质量最高（任何一次注入都常驻）；
- 变更最谨慎：core 更新需要更高共识阈值（如 dyad scope 一致同意），且 supersede 链完整保留（"你以前认为…，现在认为…"是关系记忆的一部分）。

## 6. 检索与注入（Recall，面向单次效率）

### 6.1 预算分配（硬上限）

| 槽位 | 预算（示例） |
|---|---|
| core（当前 scope 画像） | ~600 token |
| 话题相关 semantic/procedural | ~800 token |
| 相关虚构世界 canon 提示 | ~300 token（命中时） |
| 上限 | 硬顶，防止记忆吃光窗口 |

### 6.2 混合召回 + 重排

- 召回：向量语义 + 关键词/实体（人名、日期、专名、设定词）并集；
- 过滤：`world` 与 `scope` 必须匹配当前上下文（跨世界内容只能经映射边进入）；
- 重排：`score = w1·语义 + w2·recency + w3·importance + w4·共识度 − w5·age`；
- 注入格式：改写为陈述句干条 + `(记于 …)` 时效标注 + 世界标签。

### 6.3 自动 vs 按需

- 自动注入负责"不该问的都知道"（高概率需要、低体积）；
- Search 工具负责"问了才知道的"（低概率、高体积）——**决策依据是预判概率，不是内容好坏**。

## 7. 引擎五（推理层的第五台）：跨世界桥推理

跨世界不做自由联想，只走显式映射边（02 §6）：

- **结构投影**：把世界 A 的关系结构投影到世界 B 作假设推演（"这段感情像《命运石之门》的哪条世界线"→ 用该结构给用户现实处境一个可讨论的模型）；
- **隐喻索引**：虚构世界的设定作为理解现实的模板（用户意义系统的高密度入口）；
- **跨世界事实不允许直接互相 attack**；类比只产生候选假设，必须回到各自 world 的判据验证；
- 代码世界 ⇄ 现实：事故（real）→ 复现（virtual 测试）→ 修复 → 上线（real）是同一个桥的标准动作。

## 8. 推理成本控制

- 裁决惰性触发；蒸馏批量调度（非每回合）；
- 重蒸馏/全量重建放空闲期，带优先级队列；
- 可解释优先：每次裁决/共识输出得分卡，供审计与调试，避免黑箱传播错误；
- 所有 LLM 参与的步骤都产生"推理痕迹"（prompt 摘要 + schema 版本）写入基岩——**推理本身也是记忆**，未来更好模型可复核旧推理。
