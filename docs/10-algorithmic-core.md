# 10 · 符号推理内核：让事实推理脱离 LLM 依赖

## 1. 目标与定位

本文定义 Alaya 推理层的**确定性内核**：论证传播、共识融合、规则闭包、矛盾判定、可计算裁决全部以**纯算法**执行——确定性、可复现、可验证，不依赖任何 LLM 服务。

LLM 的职责被压缩到唯一的**语义翻译边界**（自然语言 ⇄ 符号）。这一层划分的意义：

- 内核可在 LLM 服务不可用/被隔离时**降级照常运行**（存量事实照常裁决）；
- 内核是纯函数，可单测、属性测试、形式化验证——适用于要求"结论可重放、行为可预测"的**关键/严肃场景**（生产数据面、审计、合规、长时间无人值守）；
- LLM 的随机性与不可预测性被隔离在边界，风险可控、可替换、可重跑。

设计前提：**一旦信息变成符号（quad + 受控谓词 + 实体 ID），其后的全部推理不再需要意义理解。** 本内核的严格正确性限定在封闭符号空间内；开放语义空间由归一化器在入口处理。

## 2. 双层架构

```
不可信/非结构化输入（自然语言、事件、外部陈述）
      │
      ▼
┌───────────────────────────────┐   ← 语义翻译边界（LLM adapter）
│ 归一化：文本 → 受控 quad       │      薄 · 可关 · 可换 · 可重跑（有源可审计）
└──────────────┬────────────────┘
               ▼  符号（进入纯算法世界）
┌──────────────────────────────────────────────────────┐
│ 符号推理内核（本文主题）                               │
│  论证传播 · 共识融合 · 规则闭包 · 矛盾判定 ·          │
│  可计算裁决(oracle) · 检索与预算                      │
└──────────────────────────────────────────────────────┘
```

类比编译器：前端解析（不可靠但只过一次）与优化器/后端（纯算法、可证明）分离。

## 3. 内核算法清单与选型

### 3.1 置信度传播 —— 主观逻辑（Subjective Logic, Jøsang）

每条声称持有 opinion `ω = (b, d, u, a)`（相信 / 不相信 / 不确定 / 先验原子性）。全部推理用封闭代数算子：

| 算子 | 用途 | 性质 |
|---|---|---|
| 折扣 discount | 证据可信度加权 | 代数封闭 |
| 共识 consensus | 多方 opinion 融合（scope 内） | 结合律/交换律，收敛有界 |
| 合取/析取 | 多证据组合 | 代数封闭 |

- 相比"让 LLM 打分"：opinion 融合结果**可复现、可审计、可重放**；
- 每条裁决输出一张得分卡：哪些证据、哪些算子、何种参数、中间值——可解释是硬要求。

### 3.2 论证语义 —— Dung 抽象论证框架

`attack` 边给定后，用图算法求 grounded / preferred 扩展：

- 哪些声称在论证图中"成立"是**可判定**问题（ASP/图算法求解）；
- 有争议的声称显式标记 `contested`，不进自动注入，等待新证据或语义复核。

### 3.3 规则闭包 —— Datalog 风格推理

world ontology 中的传递性、对称性、subclass、逆反关系用规则引擎增量维护：

- "A 依赖 B ∧ B 依赖 C ⇒ A 依赖 C" 类结论可证明、可增量更新；
- 闭包结果同样入基岩留痕（推导链可溯源）。

### 3.4 矛盾判定（符号层）

当谓词来自受控 ontology 且声明互斥/逆反（`disjoint` / `inverse`）：

- 同一 `subject + predicate`、不同 `object` 且 object 类互斥 ⇒ **算法可判矛盾**；
- 无法符号判定的疑似冲突标记 `needs_semantic_review`，排队交边界异步复核——**不阻塞主路径**。

### 3.5 可计算裁决（oracle）

凡 world 具备明确规则，裁决即确定性计算，不需要 LLM：

| world 类型 | 裁决方式 |
|---|---|
| 代码世界 | 测试/类型检查/编译运行（测试即裁决） |
| 虚构世界 | 宪章规则引擎推演 canon 一致性 |
| real 世界 | 预测模型 → 等待观测比对 |

代码世界是纯算法裁决的范式样本：编译器 + 测试运行器处理代码事实，LLM 只在写测试/代码时充当翻译器。

## 4. 让内核可行的两条工程铁律

1. **语义归一化在入口一次性完成，可缓存、可重跑。**
   归一化到受控谓词与实体 ID 后，语义等价 ⇒ 同一符号，语义矛盾降级为符号矛盾，算法即可判定。归一化产物带来源与 schema 版本；换更好的模型可全量重归一化（基岩不动，只换符号视图）。

2. **world 越封闭，纯算法占比越高。**
   world 宪章自带受控词汇表。代码世界接近 100% 封闭；虚构世界取决于设定结构化程度；real 世界开放度最高，但常见 Agent 话题（偏好、事实、项目状态）仍可受控化。

## 5. 能力边界（诚实声明）

纯算法内核**不能**做开放域语义理解：ontology 未覆盖的新话题、依赖世界知识才能判断的微妙支持/反驳、跨领域类比发现。这些本质是意义问题。

边界管理原则：

- **不假装语义**：符号层只能判定的就判定，判不了的就排队复核，绝不猜测后当作算法结论；
- **可降级运行**：边界关闭时内核照常工作——已结构化的声称照常传播/共识/闭包/检索，只是无新声称进入；
- **边界可替换**：翻译器是 adapter（见 06 API 契约），随机性被隔离在边界；
- **归一化错误可修正**：错误有源、可重跑，修正后内核结论自动重算——内核本身不会错，错的只会是输入符号。

## 6. 收益

| 属性 | 说明 |
|---|---|
| 确定性 | 同一输入永远同一输出——裁决可重放、可审计 |
| 可验证 | 内核纯函数：单测 + 属性测试（proptest）+ 关键协议模型检查 |
| 可脱离外部服务 | 内核不依赖任何 LLM API，可在隔离/离线环境裁决存量事实 |
| 可信边界可证明 | 可信部分收敛到算法内核；LLM 不确定性被隔离并限界 |
| 语义层可进化 | 换更强模型 = 重新归一化，内核与数据均不受影响 |

## 7. 与推理面其余部分的关系

- 蒸馏/总结是**生成任务**，天然生成式，留在边界侧（后台、sleep-time 调度），不属于推理内核；
- 检索/预算注入：混合召回用向量/倒排（算法），rerank 打分是数值公式（算法），归一化后的注入格式化为纯文本组装（确定性）；
- 06 API 中 `/adjudicate` 默认走内核；`?semantic=true` 才显式请求边界侧复核。

## 8. 实现顺序建议

1. 先落地**主观逻辑 opinion 结构 + 共识/折扣算子**（纯函数，几百行）；
2. 再落地论证图与 grounded 扩展求解（图算法）；
3. 矛盾判定的符号层（依赖 world ontology 的 disjoint/inverse 声明）；
4. 归一化边界作为 adapter 接入，并用"重放内核 vs 人工判定"评估集监控归一化质量；
5. oracle（先做代码世界的测试即裁决，范式最成熟）。
