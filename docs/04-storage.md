# 04 · 存储与数据管理

本层回答：**这些数据用什么结构存、如何寻址、如何保真、如何长大而不腐烂、如何分布。**

## 1. 存储选型总表

| 地质层 | 形态 | 候选技术 | 说明 |
|---|---|---|---|
| 基岩 Bedrock | 内容寻址、追加式事件日志 | 对象存储/本地文件 + 哈希链（git/IPFS 思想）；或 Kafka/EventStore 类 | 不可变、可复制、可审计 |
| 声称/论证层 | 属性图 + 论证边 | 图库（Neo4j/ArangoDB）或 SQL + 显式边表 | 双时间、scope/world 索引 |
| 共识/世界元数据 | 文档/关系 | SQLite（单机）/ PostgreSQL（服务化） | 小、热、事务性强 |
| 世界宪章 | 版本化文档（JSON/YAML） | 文件 + 内容寻址 | 人类可读、可 diff |
| 派生层 | 向量/倒排/摘要缓存 | HNSW（Qdrant/pgvector）+ BM25 + 摘要缓存 | 随时可重建，**允许丢** |
| 隐喻/映射索引 | 图边 | 随声称层 | 跨世界参照 |

**硬规则：派生层永远不是真源。** 任何二进制、向量、私有格式都只是从真源（人类可读、可导出、可 diff）重建的缓存。

## 2. 寻址与标识（身份双轨）

两套身份必须分离——分别回答"发生了什么"与"什么在延续"：

### 2.1 内容寻址（保忠实）

每个基岩事件、每条声称/共识对象都有内容哈希 id：

写入格式在 M1 就固定为**三列**（内容寻址与哈希链是两种职责，不能压在一个键上）：

```
content_hash = H(canonical(payload) + schemaVersion)              // 去重/幂等：同内容必同键
link         = H(content_hash + prev_chain_hash + scope_seq)      // 因果/审计/篡改可见
claim_key    = H(subject_key ‖ predicate ‖ object ‖ worldId ‖ norm_ver)  // 声称去重
```

- **content_hash 只对"事件本质"寻址**：`canonical(payload)` 必须明确定义参与字段集——排除 `recordedAt`、来源、传输噪声；`observedAt` 也不参与（否则多来源时间戳差异会导致同一事件分裂），仅作为事件属性保存；
- **link 承载哈希链**：篡改任一字节或截断尾部，验证器必须报错（忠实性的数学保证）；
- 链形态：**per-scope 单调 seq 的局部链 + 跨 scope 因果 DAG**（与 §3.2 一致），不是一条全局链——否则并发写者要么被迫串行化（单点），要么分叉后无法验证；
- 若去重键取含前件的 `event_id`，重蒸馏会产出全新 id，历史 claim 的证据引用将悬空、supersedes 链断裂——直接违反不变式①与⑤。

### 2.2 稳定实体 ID（保连续）

"十年的用户"仍是同一个人，"连载二十年的作品"仍是同一世界：

```
EntityRef = urn:alaya:<kind>:<namespace>:<slug>
  例: urn:alaya:person:user:garden
      urn:alaya:world:fate
      urn:alaya:module:repo:alaya:ingest
```

实体随时间演化 = **entity timeline**：一个稳定 ID 下一串版本化状态（快照或增量），而不是被覆盖的单行记录。身份双轨的边界：内容寻址给"这刻发生的事"指纹；稳定 ID 给"在延续的谁/什么"锚点。

## 3. 时间：双时间 + 因果偏序

### 3.1 双时间

- **valid time（observedAt）**：该断言/事件在 world 内为真的时间（剧情时间、代码提交时间、现实发生时间）；
- **transaction time（recordedAt）**：该记录被写入 Alaya 的时间。

没有双时间，"我昨天认为 X、今天认为 ¬X"就不可表达；虚构世界的时间线与现实记录时间必须分离。

### 3.2 因果偏序（分布式下无全局时钟）

- 基岩事件间用**因果版本向量 / 向量时钟**排序，而非全局时间戳；
- 全局总序是"单一故事"的幻觉；因果 DAG 才忠实于"历史如何发生"；
- 同 scope 内需要全序时，用 scope 内单调序列（如 per-scope log sequence number）补充。

## 4. 生命周期与保留策略

| 层 | 可删除性 | 策略 |
|---|---|---|
| 基岩事件 | 默认永不删 | 仅法律/用户强制删除时写**墓碑 tombstone**（内容擦除、哈希与元数据留存，保证"曾被记录"的事实可审计） |
| 声称/论证 | 不物理删除 | supersedes 置灰；随 scope 消散可 `archived`（移冷层） |
| 共识对象 | 不物理删除 | 同声称层；异议永不删 |
| 派生层 | 随时可删 | 重建脚本化；这是唯一允许 GC 的层 |

**遗忘发生在哪里？** 发生在派生层与注入层——低 importance、长期未命中的条目从"自动注入"降级为"仅可检索"，再降为归档。基岩保留的是原料；遗忘是对原料的**访问控制与预算控制**，不是销毁。这与"记忆是意义的选择性保存"一致：系统删除的是"不值得注入的派生视图"，不是"发生过的事实"。

## 5. 索引管理

- **派生索引从真源异步构建**：向量 + 倒排 + 摘要金字塔，全部由基岩/声称层重建，带 epoch 版本号；
- **schema 演化**：所有事件带 `schemaVersion`；读取端按版本解码；迁移 = 新版本读取器，不 rewrite 历史；
- **embedding 换代**：换模型 = 全量重 embed（后台任务），零数据损失——向量维度变化只影响派生层；
- **写放大控制**：事件先顺序追加（基岩），中间层异步物化（声称/论证图/派生索引），保证写入路径简单快速。

## 6. 基岩快照与增量重放

**问题**：§4 规定基岩默认永不删除。这保证了忠实性，但隐含一个代价——
**若所有派生物都从创世事件开始重放，重建时间随历史长度线性增长。**
同构架构的实践者已明确承认这一点：重放成本随日志长度增长，长寿命运行最终需要 checkpoint 与 compaction，
且承认自己尚未提供（[12 §7.1](12-academic-evidence-on-agent-memory.md)）。

**原则：不删事件，但不必从创世重放。**

```
基岩事件流（永不删）
  e1 ····· e_k ····· e_m ····· e_n
                 │              │
            快照 S_k        快照 S_m        重建 = 从最近快照 + 其后增量
```

| 项 | 设计 |
|---|---|
| 快照内容 | 某 scope 在 `scope_seq = k` 处的物化状态（声称 / 共识 / 实体时间线的当前视图） |
| 快照的地位 | **派生物**：可删、可重建；不替代事件，不改动 §4 的保留策略 |
| 校验 | 快照携带该位置的 `link` 哈希；从快照重建后的状态须与全量重放一致，否则报错 |
| 触发 | 重建耗时超阈值，或 `scope_seq` 增长超阈值（两者都是可监控信号） |
| 边界 | 快照只加速**重建**，不加速**历史查询**——查"某条声称的完整演变"仍须回溯相关事件 |

**与不变式①的关系**：不变式是"事件永不丢失"，不是"永不使用快照"。
快照若损坏或被篡改，可从事件重放恢复——这正是快照可以是派生物的原因。

**待定**：快照粒度（per-scope 还是全局）与存储位置（是否与事件同库）尚未决定。

## 7. 派生依赖图与失效传播

**问题**：§4 规定遗忘发生在派生层、基岩永存。但**基岩不变不等于派生层自动正确**——
当一条声称被 supersede，依赖它的上层摘要、画像、缓存注入不会自动失效。
外部调研把这条列为未解决的开放问题：当前的 forget-guard 机制无法保证
被撤销的事实不再影响下游摘要、画像或缓存检索（[12 §7](12-academic-evidence-on-agent-memory.md)）。

对本层这是**不变式完整性的缺口**：不变式④要求"更新不物理删除，supersedes 留时间线"，
但若上层蒸馏物继续携带旧值，"留时间线"就退化成了"删不掉错误"。

**原材料已经具备**：§8 要求"每级都带指向下级的证据引用"。把这条要求升级为显式依赖边：

```
core 条目 ──derived_from──▶ semantic 条目 ──derived_from──▶ 声称 ──evidence──▶ 基岩事件
     ▲                                                                             ▲
     └───────────────── 失效沿依赖边反向传播 ───────────────────────────────────────┘
```

| 机制 | 设计 |
|---|---|
| 依赖边 | `derived_from`：派生条目 → 其依据（声称 / 下层条目 / 事件） |
| 触发 | 声称被 supersede、置为 `dormant`（03 §2.3）、或收到 `attacks` |
| 传播 | 沿依赖边反向标记所有下游条目为 `stale_derived` |
| 处置 | `stale_derived` 条目**退出自动注入**，并进入重蒸馏队列（优先级高于常规蒸馏） |
| 不做 | **不级联删除**——旧派生条目仍可被检索与审计，只是不再自动生效 |

**无源的派生条目等同于污染**：若某条派生条目无法追踪到依赖，必须标记为不可信来源，
而非默认有效。传播完备性是本层的验收项之一（见 §10）。

**与 epoch 的关系**：§5 的 epoch 机制处理"换模型全量重建"（粗粒度、低频）；
本节处理"单条证据失效的增量传播"（细粒度、高频）。两者互补，不可互相替代。

## 8. 多分辨率金字塔（长大而不腐烂）

量级增长后，查询不能总触达基岩。金字塔从基岩蒸馏出多级分辨率视图：

```
基岩事件 ──▶ 情节/会话摘要 ──▶ 语义条目 ──▶ 核心画像（core）
   (证据)       (episodic)       (semantic)    (identity)
```

- 每级都带指向下级的证据引用（可溯源、可下钻）；
- 每级都是派生物：模型换代即重蒸馏；
- 查询在合适的分辨率着陆，需要细节时下钻；
- **金字塔同时是"遗忘"的载体**：注入预算只作用于高层，冷门细节自然沉底。

**粒度匹配优先于结构选择**。外部受控实验显示：表示的粒度与查询类型的匹配度，
比"结构是否更高级"更能决定效果——同一结构在粒度错配时**反而有害**
（[12 §2.2](12-academic-evidence-on-agent-memory.md)）。两条可操作方向：

- **宁细勿粗**：实测中拆分过细的代价约 −2 个点，拆分过粗约 −6 个点，**代价非对称**。
  因此默认应偏细，靠"查询时下钻"而非"写入时粗合并"来控制体积；
- **检索宽度同理**：top-k 增大到某一点后性能**下降**（召回仍在涨，但噪声压垮推理），
  说明"多召回"不是免费的。§10 的预算硬顶与此一致。

## 9. 分布式与所有权

全人类级记忆不可能活在单一数据中心，且"记忆属于每个人"：

- **内容寻址副本**：谁都可以持有完整/部分副本，无人拥有"唯一正本"；
- **scope 分片**：以 scope 为一致性单元，scope 内可自洽、可离线运作（个人助手可完全本地运行，隐私优先）；
- **CRDT/最后写入不覆盖**：并发追加天然收敛（只追加模型没有"更新冲突"），冲突只发生在裁决层（由共识机处理，而非存储层）；
- **冷热分层**：热数据（近期/高 importance scope）与冷数据（归档）分离，迁移不破坏内容寻址链。

## 10. 数据管理的验收标准

1. 任意一条声称可沿证据链下钻到基岩事件（可审计）；
2. 任意派生索引可整体删除并从真源重建（可恢复）；
3. 任何"更新"操作在存储层不存在（只追加；更新是语义层动作）；
4. 跨机器副本的篡改可被哈希链检测（可信任）；
5. 个人 scope 的数据可完整导出、可完全删除（可携带、可遗忘）。
6. 重建可从最近快照增量进行，且结果与全量重放**逐位一致**（可加速而不失真）；
7. 任一声称失效后，其下游派生条目在有限步内被标记 `stale_derived` 且可追踪来源（可传播）。
