# 04 · 存储与数据管理

本层回答：**这些数据用什么结构存、如何寻址、如何保真、如何长大而不腐烂、如何分布。**

## 1. 存储选型总表

| 地质层 | 形态 | 候选技术 | 说明 |
|---|---|---|---|
| 基岩 Bedrock | 内容寻址、追加式事件日志 | 对象存储/本地文件 + 哈希链（git/IPFS 思想）；或 Kafka/EventStore 类 | 不可变、可复制、可审计 |
| 声称/论证层 | 属性图 + 论证边 | 图库（Neo4j/ArangoDB）或 SQL + 显式边表 | 双时间、scope/world 索引 |
| 共识/世界元数据 | 文档/关系 | SQLite（单机）/ PostgreSQL（服务化） | 小、热、事务性强 |
| 世界宪章 | 版本化文档（JSON/YAML） | 文件 + 内容寻址 | 人类可读、可 diff |
| 派生层 | 向量/倒排/摘要缓存 | HNSW（Qdrant/pgvector）+ BM25 + 摘要缓存 | 随时可重建，**允许丢** |
| 隐喻/映射索引 | 图边 | 随声称层 | 跨世界参照 |

**硬规则：派生层永远不是真源。** 任何二进制、向量、私有格式都只是从真源（人类可读、可导出、可 diff）重建的缓存。

## 2. 寻址与标识（身份双轨）

两套身份必须分离——分别回答"发生了什么"与"什么在延续"：

### 2.1 内容寻址（保忠实）

每个基岩事件、每条声称/共识对象都有内容哈希 id：

```
event_id  = H(事件负载 + 前件哈希)   // 哈希链：篡改即暴露
claim_id  = H(quad 负载 + schemaVersion)
```

- 哈希链让任何篡改在副本间立刻可见——"忠实性"的数学保证；
- 内容寻址天然支持去重与合并（同一事件从两个来源到达 = 同一 id）。

### 2.2 稳定实体 ID（保连续）

"十年的用户"仍是同一个人，"连载二十年的作品"仍是同一世界：

```
EntityRef = urn:alaya:<kind>:<namespace>:<slug>
  例: urn:alaya:person:user:garden
      urn:alaya:world:fate
      urn:alaya:module:repo:alaya:ingest
```

实体随时间演化 = **entity timeline**：一个稳定 ID 下一串版本化状态（快照或增量），而不是被覆盖的单行记录。身份双轨的边界：内容寻址给"这刻发生的事"指纹；稳定 ID 给"在延续的谁/什么"锚点。

## 3. 时间：双时间 + 因果偏序

### 3.1 双时间

- **valid time（observedAt）**：该断言/事件在 world 内为真的时间（剧情时间、代码提交时间、现实发生时间）；
- **transaction time（recordedAt）**：该记录被写入 Alaya 的时间。

没有双时间，"我昨天认为 X、今天认为 ¬X"就不可表达；虚构世界的时间线与现实记录时间必须分离。

### 3.2 因果偏序（分布式下无全局时钟）

- 基岩事件间用**因果版本向量 / 向量时钟**排序，而非全局时间戳；
- 全局总序是"单一故事"的幻觉；因果 DAG 才忠实于"历史如何发生"；
- 同 scope 内需要全序时，用 scope 内单调序列（如 per-scope log sequence number）补充。

## 4. 生命周期与保留策略

| 层 | 可删除性 | 策略 |
|---|---|---|
| 基岩事件 | 默认永不删 | 仅法律/用户强制删除时写**墓碑 tombstone**（内容擦除、哈希与元数据留存，保证"曾被记录"的事实可审计） |
| 声称/论证 | 不物理删除 | supersedes 置灰；随 scope 消散可 `archived`（移冷层） |
| 共识对象 | 不物理删除 | 同声称层；异议永不删 |
| 派生层 | 随时可删 | 重建脚本化；这是唯一允许 GC 的层 |

**遗忘发生在哪里？** 发生在派生层与注入层——低 importance、长期未命中的条目从"自动注入"降级为"仅可检索"，再降为归档。基岩保留的是原料；遗忘是对原料的**访问控制与预算控制**，不是销毁。这与"记忆是意义的选择性保存"一致：系统删除的是"不值得注入的派生视图"，不是"发生过的事实"。

## 5. 索引管理

- **派生索引从真源异步构建**：向量 + 倒排 + 摘要金字塔，全部由基岩/声称层重建，带 epoch 版本号；
- **schema 演化**：所有事件带 `schemaVersion`；读取端按版本解码；迁移 = 新版本读取器，不 rewrite 历史；
- **embedding 换代**：换模型 = 全量重 embed（后台任务），零数据损失——向量维度变化只影响派生层；
- **写放大控制**：事件先顺序追加（基岩），中间层异步物化（声称/论证图/派生索引），保证写入路径简单快速。

## 6. 多分辨率金字塔（长大而不腐烂）

量级增长后，查询不能总触达基岩。金字塔从基岩蒸馏出多级分辨率视图：

```
基岩事件 ──▶ 情节/会话摘要 ──▶ 语义条目 ──▶ 核心画像（core）
   (证据)       (episodic)       (semantic)    (identity)
```

- 每级都带指向下级的证据引用（可溯源、可下钻）；
- 每级都是派生物：模型换代即重蒸馏；
- 查询在合适的分辨率着陆，需要细节时下钻；
- **金字塔同时是"遗忘"的载体**：注入预算只作用于高层，冷门细节自然沉底。

## 7. 分布式与所有权

全人类级记忆不可能活在单一数据中心，且"记忆属于每个人"：

- **内容寻址副本**：谁都可以持有完整/部分副本，无人拥有"唯一正本"；
- **scope 分片**：以 scope 为一致性单元，scope 内可自洽、可离线运作（个人助手可完全本地运行，隐私优先）；
- **CRDT/最后写入不覆盖**：并发追加天然收敛（只追加模型没有"更新冲突"），冲突只发生在裁决层（由共识机处理，而非存储层）；
- **冷热分层**：热数据（近期/高 importance scope）与冷数据（归档）分离，迁移不破坏内容寻址链。

## 8. 数据管理的验收标准

1. 任意一条声称可沿证据链下钻到基岩事件（可审计）；
2. 任意派生索引可整体删除并从真源重建（可恢复）；
3. 任何"更新"操作在存储层不存在（只追加；更新是语义层动作）；
4. 跨机器副本的篡改可被哈希链检测（可信任）；
5. 个人 scope 的数据可完整导出、可完全删除（可携带、可遗忘）。
