## 0. 为什么研究它

Alaya 的诸多设计选择（不可变基岩、scope 共识、蒸馏金字塔、派生层可重建）在 2025–2026 年
恰好成为一个活跃研究领域的主战场：**LLM Agent 的长期记忆系统**。

这一领域已经积累了两类可用证据：

1. **受控实验**：多篇论文做了"记忆底座"的隔离对照（同一模型、同一任务，只换记忆结构），
   能够回答"哪种表示更好"这类此前只能靠直觉的问题；
2. **系统实测**：Stanford 等团队对 10 个主流记忆系统做了端到端的能耗、延迟、footprint 测量，
   把"记忆系统的真实成本"从猜测变成数字。

更重要的是，这一领域已经产生了**足够多的否定性结果**——哪些做法被证伪、哪些假设不成立。
对一个尚未落地的设计而言，否定性证据比肯定性证据更便宜。

本文汇总约 30 篇论文。**它不是文献综述**，只记录那些足以改变设计判断的证据。

## 2. 四个被证据否定的流行假设

### 2.1 【实测】"上下文窗口够大就不需要记忆系统"

**否定。** SCALE-QA（2608.25655）构造了"扁平、混合主题、无会话边界"的长对话，
问题需要从早期某段**休眠的局部约束**中恢复答案：

| 条件 | Full Context | TSIM（按情节重建的记忆） |
|---|---|---|
| GPT-4o-mini @128k | 29.8%（证据包含率 **100%**） | **73.8%**（约 1k tokens） |
| Gemini 2.5 Flash @1M | 87.2%（23.87s，1.05M tokens） | **96.5%**（2.2s，约 1.3k tokens） |

关键在第二列括号：**证据 100% 在场，模型仍答不对**。作者把该失效命名为
**episode integrity failure（情节完整性失效）**——证据可见但碎片化，
系统检索到"看似合理的片段"而非"使局部约束成立的完整情节"。

**设计含义**：这不是上下文长度问题，是**检索单元的选择问题**。作者的主张是
检索单元应是"推断出的情节"（operative episode），而非固定 token 窗口或单条记忆项：
固定 128/256/320 token 窗口的全证据 recall@5 为 0.719/0.647/0.577，TSIM 为 0.810。

### 2.2 【实测】"结构化程度越高越好（图 > 扁平）"

**否定。** 这是本次调研中被反复证伪的一条，且有多篇**受控**实验：

| 证据 | 结论 |
|---|---|
| UnifiedMem（2601.01280，唯一逐阶段受控 flat vs graph 对照） | 图的优势**只出现在检索召回**和"证据用原始会话"时（+0.13）；一旦证据按 key 粒度取用，**图反而更差**（−0.06） |
| 同上 | 图的收益**强烈依赖构建模型能力**：8B 构建几乎无增益（0.614→0.620），gpt-4o-mini 构建 +0.132（0.760→0.892） |
| StructMemEval（2602.11243） | 同 backbone 下 **Mem0 0.30 > Mem0-G 0.22**，且 Mem0-G 的 state-tracking 归零 |
| 2608.28978 | Graph RAG 整体不如扁平检索（F1 0.417 vs 0.468，配对 bootstrap CI 排除零）；"回忆助手原话"类问题 0.607 vs **0.911** |
| AtomMem（2606.19847） | 完整版用 **29.6× 的 token** 把多跳 F1 从 37.03 再提到 42.50 |

2608.28978 给出的机制解释值得记住：把一轮对话分解成实体与关系，
会**丢掉"哪一条陈述被强调"这类表面形式**，而该类问题恰恰依赖它。
作者同时明确限定了结论边界（单模型、单 benchmark），不应外推为"图记忆普遍更差"。

**真正的结论不是"用不用图"，而是粒度匹配**：图适合承载跨会话的关系与时间演化，
不适合替代高密度的事实聚合单元。失败信号很清晰——**当图的粒度比 ground truth 更粗或更细时，图反而有害**。

### 2.3 "瓶颈在检索"——被部分否定，且论文之间互相矛盾

**部分否定，且论文之间互相矛盾——这个矛盾本身值得记录。**

**支持"瓶颈在使用"的一侧（【实测】）**：

- MemTrace（2606.17328）把 300 个失败探针做 reach/use replay：**只有 7.0% 是检索未命中，
  73.3% 是"检索器可达但未解决"**。对这些子集重跑 open-book oracle，
  **13 个系统全部恢复到 80.4–83.9%**（pooled +81.8 个百分点）。
  即：证据可达却未被使用的频率，约是证据不可达的 **10 倍**。
- MERIT（2609.05441）用独立的 value tracing 测到 **Ignore Rate 0.45**
  （hard tier，检索块中含正确的最新值）；即便给出干净完整的 transcript，
  多事实场景下 Ignore Rate 仍达 **0.50**。
- StreamMemBench（2606.14571）：**Fidelity 接近 100%，但 IEU 仅 24–42%**，落差最大约 76 个百分点。

**支持"瓶颈在检索"的一侧（【实测】）**：

- MemConflict（2605.20926）的失败分解给出相反结论：检索失败占主导
  （A-Mem 74.3:25.7、Letta 75.9:24.1、MemOS 77.7:22.3、Mem0 91.4:8.6），
  只有 LangMem 在动态冲突下利用率失败反超（46.1:53.9）。

两者测的探针集与归因定义不同，因此**不构成直接冲突，但说明"检索 vs 使用"的归因方法尚未标准化**。
可确定的结论是：**利用率问题至少与检索问题同量级，而当前工程投入几乎全部在检索侧**。

### 2.4 【实测】"更强的模型能替代记忆"

**否定。** MERIT：无记忆条件在依赖记忆的任务上对**所有**模型为 0.000
（含 Claude Opus 4.8 / Sonnet 5，且经 leak check 验证无其他可达路径）。

更值得注意的是**模型换代没有修好任何一条失效模式**：

| 失效模式 | 新一代模型上的表现 |
|---|---|
| 时间轨迹重建 | MemTrace 中 GPT-5-nano 从 38.4 掉到 6.5；MemOps 中 DeepSeek-V4-Flash long-context 仅 0.305 |
| 检索式记忆的修订崩溃 | MERIT 的 Sonnet 5 spot-check 仍复现（C2=0.75 vs C3/C4=1.00） |

**这是架构性失效，不是能力性失效。**

## 3. 被多篇独立验证的实现原则

### 3.1 【实测】先投写侧，再投读侧

Infini Memory（2606.10677）的消融给出定量对比：

| 变更 | 效果 |
|---|---|
| 去掉维护（split & merge） | **−6.7** |
| 检索从 hybrid 升级到 agentic | +3.3 |

AtomMem（2606.19847）给出同向证据：**仅用原子事实 + 扁平检索的变体**，
以全场最低的 722K tokens 把多跳 F1 从 20.97 提到 37.03（+76.6% 相对提升）。
作者的原话：*"Sophisticated system orchestration cannot compensate for flawed memory representations."*

Harness（2608.15008）把这条上升为设计规则：**trade read breadth for write depth**
——每查询检索更少条目，把预算投入写入时的蒸馏与结构化。
其机制解释是 attention probe：检索深度增加时，模型注意力从任务上下文转向检索块；
这对 QA 有益（答案恰在检索块中），对 agentic 决策**有害**（策略需要关注当前观测）。

### 3.2 【实测】保留原始证据，不要激进压缩

四篇独立指向同一方向：

| 论文 | 证据 |
|---|---|
| UTILMEM（2608.30508） | 保留原始 turn 的 NaiveRAG（NR 58.9–59.3）**大幅优于** Mem0（NR 17.3 / DR 98.3） |
| SubtleMemory（2606.05761） | preservation 最强的两个系统，共同点是"除结构化记忆外还保留原始 session" |
| NapMem（2607.05794） | 四层金字塔的底层是 append-only 原始对话 |
| Agent Zero（2608.29606） | 批评 Memobase"一次抽取错误就永久不可恢复" |

一个补充观察：MEMPROBE（2606.24595）中**无记忆 agent 的任务完成率 99.935%**，
与所有记忆系统（99.871–99.935%）无实质差异。激进压缩换来的那点收益，
在行为分上根本测不出来——这既是"保留原始证据"的支持证据，也是评测方法论的问题（见 §6）。

### 3.3 【实测】更新用"标记取代 + 双向链"，不要覆盖

DCPM（2606.09483）的 `supersede` 机制是本次调研中**最强的单一预测因子**：

> LongMemEval knowledge-update 类问题上，**答对的查询 78% 在读取时穿过至少一条
> supersedes 指针，答错的只有 31%**。

且 DCPM 的读路径**完全不调用 LLM**（向量命中 + 指针遍历，O(log N + k̄)），
却在 LongMemEval 上超过 long-context agent **+5.53**。

写侧动作集跨系统高度收敛为四类（create / summarize / promote / invalidate），
**物理删除是少数派**。理由有三条实测支撑：
① knowledge-update 类问题惩罚覆盖式写入；② 能穿过修订链是答对的关键；
③ 要表达"这条记忆已失效但确实存在"需要一个对象（MRMS 的 negative context 槽位）。

### 3.4 【实测】粒度宁可偏细

Infini Memory 的拆分阈值扫描是唯一的完整参数曲线，且**非对称**：

| 阈值 | 文档数 | 相对默认 |
|---|---|---|
| ≥1000 | 762 | −2.0 |
| ≥3000 | 319 | −1.7 |
| ≥5000（默认） | 322 | 基准 |
| ≥7000 | 280 | **−5.3** |
| ≥9000 | 255 | **−6.3** |

检索 top-k 同理：AtomMem 扫到 **>20 后性能反而下降**——召回仍在涨，但噪声压垮推理。

### 3.5 【实测】按需触发 + 确定性快路径

NapMem（2607.05794）给出了最干净的对照（**记忆源完全相同，只换访问方式**）：

| 变体 | 分数 |
|---|---|
| Full（主动导航） | 62.74 |
| w/o navigation（被动检索替换） | 54.08（**−8.66**） |

但 DCPM 是明确反例：当"该查什么"能被结构化指针**确定性地**回答时，
主动检索是多余的（且零 LLM 调用更便宜）。

**结论不是"主动优于被动"，而是"按需触发的主动 + 确定性的快速路径"。**
配套证据：未训练的策略会滥用记忆工具——NapMem 未加 RL 时在非记忆任务
（GPQA-D）上有 **34.51% 的无谓记忆调用**，RL 后降到 6.90%。

工程形态在 Agent Zero（2608.29606）中收敛为：
**intent gate（自包含轮次零延迟直通）→ source router → 并发检索 → 合并**。

### 3.6 可操作参数（跨论文汇总）

以下数值来自不同系统、不同 benchmark，**只应作为量级参考，不应直接照搬**。

| 参数 | 取值 | 敏感性证据 |
|---|---|---|
| 事实检索 top-k | 10 | >20 后退化（AtomMem） |
| dense / keyword 混合比 | 0.7 / 0.3 | 两篇独立工作重合（DCPM、AtomMem） |
| RRF 常数 k | 60 | 两篇独立工作相同（Agent Zero、NapMem） |
| 文档拆分阈值 | 略高于 4096 chunk 预算 | 偏细安全、偏粗代价大（Infini） |
| 工具调用预算 | ≤4 轮（训练）/ ≤7 轮（检索） | NapMem / Infini |
| 图遍历跳数 | 2（实体/事件），1（时序） | AtomMem |

## 4. 个人助手的特有难题

### 4.1 【实测】检索对 ≠ 信念对

这是与通用 agent 记忆重叠最少、但对"个人助手"最致命的一块。

HorizonBench（2604.17283，UW/Meta/OpenAI/Stanford）构造了 360 个模拟用户、
6 个月、平均约 4,300 轮 / 163K tokens 的对话历史，其中用户偏好被**后续生活事件隐式改变**
（演化的偏好不会被重新陈述）：

| 结果 | 数值 |
|---|---|
| 最好的前沿模型（25 个中） | **52.8%** |
| 人类标注者 | 56–64% |
| 多数模型 | ≤ 20%（5 选 1 的随机基线） |
| 错误中选择"演化前的旧值" | 超过 **1/3**，所有 25 个模型均显著高于随机 |

**决定性证据**：把历史从 6 个月缩短到 0–14 天（约 95K tokens），
这个 gap **反而扩大**到 −5.7pp（25/25 模型全负）。
**所以这不是上下文长度问题，是状态跟踪能力问题**，且 RAG 会**精确地**返回那个过时的值
（因为它检索"最近被陈述的偏好"）。

作者给出的分解很关键：**检索失败与信念更新失败需要不同的解法**，
而既有 benchmark 无法区分二者（多数把旧值当作正确答案的近义表达）。

### 4.2 【实测】遗忘的定价

Opal（2604.02522）的 3 年合成数据回放给出了唯一的多年尺度证据：

| 指标 | 数值 |
|---|---|
| 1 年 TTL 造成的总精度差 | 7.33pp |
| 其中：**有意丢弃数据** | **5.88pp** |
| 其中：ANN 索引漂移 | 1.45pp |

**几乎全部损失来自"有意丢弃"，索引维护本身几乎免费。**
这直接说明：该优化的不是索引，而是**保留策略**。

但不遗忘的代价更大：

- Memora（2604.20006）：memory agents 的遗忘惩罚**随时间长而上升**
  （weekly 18.2 → quarterly 29.5），因为"保留旧记忆访问权而无有效遗忘"会放大不一致；
  而 LLM 的缩减随时长**下降**（32.6 → 17.8），原因是超窗遗漏而非记忆变好。**方向相反。**
- MERIT：hybrid 架构的 stale-memory harm **+0.25 @ ρ=0.3**（Holm p=0.030）。
  更值得注意的是 **LLM 抽取器会吞下 rigid pattern 会拒绝的腐蚀记录**
  （stale harm 从 ≤0.05 升到 +0.20）——**抽取器的自由度是风险来源**。
- Stanford 实测（2606.06448）：**所有被测系统默认都不遗忘**，footprint 单调增长
  （原文："bounding fleet storage requires an independent forgetting policy"）。

### 4.3 【观察】图的收益与代价在助手场景同时存在

EngramaBench（2604.21229）是唯一按查询类型分解的对照：

| 场景 | Engrama（图） | GPT-4o full-context | Mem0（扁平） |
|---|---|---|---|
| cross-space（证据从未同会话共现） | **0.6532** | 0.6291 | 0.5266 |
| adversarial abstention（应弃答） | **0.8000** | 0.9750 | **1.0000** |

即：图是唯一超过 full-context 的系统，但**只在跨会话整合这一类**；
同时它**显著损害弃答能力**——作者解释是多跳激活会带回"结构上合理但事实无关"的证据。
**对个人助手而言，这个副作用很致命**（助手最常见的失败是自信地记错，而非坦白不知道）。

## 5. 【实测】成本证据

### 5.1 端到端实测（2606.06448，Stanford，10 系统，单卡 H100）

LongMemEval 子集（约 1.8M tokens 历史、300 queries）：

| 系统 | 构造 Wall | 总能量 | **每正确答案能耗** |
|---|---|---|---|
| BM25 | 16.3 m | 582 kJ | **4,128 J** |
| embedRAG | 14.4 m | 495 kJ | 4,144 J |
| GraphRAG | 1.83 h | 2,082 kJ | 15,084 J |
| Mem0 | 4.02 h | 4,878 kJ | 50,813 J |
| A-Mem | **11.76 h** | 14,864 kJ | 116,116 J |
| Letta | **14.36 h** | 15,429 kJ | **185,873 J** |

**端到端能量跨度 26.7×，每正确答案能耗跨度 >47×。**
作者据此给出底线：结构化记忆相对扁平检索有 **28–47× 的溢价**，
*"必须以扁平检索无法提供的能力来证明：mutation、冲突消解、多类型路由或长程推理。"*

### 5.2 成本重心在构造侧，而非查询侧

- 查询延迟：Mem0 **<0.1s** vs long-context 约 **38s**（跨两个数量级）；
  原文结论是"主导变量是检索管线深度，而非 LLM 服务速度"。
- 但构造侧 A-Mem 11.76h / Letta 14.36h。
  对 LLM-mediated 系统，**构造能耗可超过 300 次查询的全部查询能耗之和**。
- **成本斜率比初始 footprint 重要**：agentic 系统的构造 token 成本随 store **超线性**增长
  （Letta 在 256K tokens 后急剧发散）。原文：
  *"An agent's long-term cost is therefore dictated by its algorithmic growth slope, not its initial footprint."*

### 5.3 成本被系统性忽视

Harness（2608.15008）对 2023–2026 年 **52 个**记忆增强系统的景观分析：

| 项 | 比例 |
|---|---|
| 报告 accuracy | 100% |
| 报告任何效率指标 | **21%** |
| 报告 management cost 与 compression ratio | **0%** |
| 同时达到 ≥3 benchmark × ≥3 效率维度 | **0 个系统** |
| benchmark 集中在 LoCoMo + LongMemEval | 62%（agentic benchmark 使用数为 **0**） |
| 只用单一 GPT 家族 backbone | 81% |

### 5.4 记忆系统的 token 相对开销（唯一正面数字）

SP-Mem（2608.16551）归一化到 full-context = 1.00：
MemOS 0.23–0.27、Mem0 0.21–0.25、Zep 0.22–0.25、SP-Mem 0.26–0.31（跨 4 个 backbone）。

**即：记忆系统把上下文 token 压到全历史的约 1/4。** 这是支持记忆系统的少数正面成本证据之一。

## 6. 评测方法论：什么叫"科学地评测"

既有 benchmark 的缺陷已被量化。Memora（2604.20006）的对照表最直观：

| Benchmark | memory consolidation (avg/max) | memory mutation (avg/max) |
|---|---|---|
| PerLTQA | 1.0 / 1.0 | 0.0 / 0.0 |
| **LoCoMo** | 1.3 / 15.0 | **0.0 / 0.0** |
| **LongMemEval** | 1.9 / 6.0 | 2.0 / 2.0 |
| Memora (Quarterly) | **28.4 / 309.0** | **14.8 / 94.0** |

补充：**LoCoMo 的 94% 问题只需 ≤2 个 prior session 的接地证据**（LongMemEval 为 85%）。
即主流 benchmark 上的大多数评测退化为"能否回忆前一个会话引入的孤立信息"。

九条正在形成的共识（各论文独立收敛）：

1. **测量单元必须从"问题行"升级**——四篇独立提出四种替代单元：
   knowledge point（MemTrace）、lifecycle operation（MemOps）、
   recovery target（MEMPROBE）、arc + 程序化终态谓词（MERIT）。
   共同理由：行级聚合把探测同一事实的多个问题当独立项，**无法固定事实、变化条件**。
2. **必须能区分记忆管线的四个阶段**：写没写进去 / 取不取得出 / 用没用上 / 用对了没有。
   实现手段包括 oracle 检查、reach/use replay、`R_dump` vs `R_retr`、value tracing。
3. **受控条件维度必须显式设计**：记忆年龄 × 问题类型 × 证据条件、冲突类型 × 冲突距离、
   难度阶梯 × 腐蚀模式。
4. **对照与防泄漏是硬要求**：无记忆地板、**leak check 必须作用于世界状态而非仅 prompt**、
   delta scoring、open-book oracle、防钓鱼 critic。
5. **成本必须进指标**：报告 token 数不等于报告边际效用。MERIT 的诚实计量把某配置的
   性价比从 ~17,300 pts/$ 打到 4,839 pts/$。
6. **多 backbone × 多种子**：MERIT 报告 embedding 检索的 **seed gap 最大 0.45**，
   跨模型跨度 **0.30–0.95** ——*单种子评测可以诚实地报出 0.45 到 0.90 之间的任何值*。
7. **Judge 可靠性必须审计**：多篇报告与人工的一致率（88.3% ~ κ=0.980）。
8. **负面结果与偏差方向必须显式声明**：如"tracer 低估利用，故 Ignore Rate 是保守上界"。
9. **行为分不足以代表记忆**：MEMPROBE 的无记忆 agent 达 99.935% 任务完成率；
   MemOps 的核心论点是"**right answer, wrong memory state**"。

**最能说明评测现状的单一事实**：同一个系统在不同 benchmark 上排名反转——
Mem0 在 UTILMEM 上是**灾难级**（NR 17.3 / DR 98.3，全场最差），
在 SubtleMemory 上是**次优系统**（69.0%）。
**任何单一 benchmark 的排名都不能作为记忆系统质量的判据。**

## 7. 未解决的空白（诚实的负面清单）

| 空白 | 证据 |
|---|---|
| **时间推理** | 全领域公认未解决：EngramaBench 上所有系统最高 0.3902；MemTrace 中 trajectory 从 fresh 到 saturated 崩塌至 6.5–13.4 |
| **多跳 × 跨文档更新** | Infini Memory：单跳 81.0 vs **多跳 35.0**，作者判定为写时巩固的结构性上限，"缺任一跳就级联失败" |
| **图损害弃答能力** | Engrama 0.8000 vs Mem0 1.0000 vs full-context 0.9750 |
| **传播完备的遗忘** | Mi-Memory 明确列为未解决：*"Current forget-guard mechanisms do not guarantee that a revoked fact ceases to influence downstream summaries, profiles, or cached retrievals."* |
| **重排** | 三篇报告都用了重排，但**没有一篇给出"重排 vs 不重排"的消融** |
| **年尺度部署** | 只有 Opal 做了 3 年**合成**回放；其余均为 roadmap item |
| **选择性披露的残余风险** | SP-Mem 自认：未覆盖再识别、多轮推断攻击、从脱敏值反推 |
| **隐私的访问模式泄漏** | Opal：*"observing which memories a system retrieves is nearly as revealing as seeing the query text itself"* |

### 7.1 一条正面证据：事件溯源架构

与 Alaya"不可变基岩 + 派生层"最接近的架构在本次调研中获得了支持：

| 工作 | 机制 | 承认的边界 |
|---|---|---|
| ActiveGraph（2605.21997） | append-only 事件日志为真源，图是日志的确定性投影；**内容寻址缓存记录 model/tool 响应**使重放确定 | 明确承认：**"Replay cost grows with log length, so very long-lived runs eventually need checkpointing or compaction, which we do not yet provide"** |
| PROJECTMEM（2606.12329） | append-only 纯文本事件日志（JSONL）+ 确定性投影；提出 **Memory-as-Governance**（记忆在动作前确定性干预） | 冷启动问题；无向量检索是有意取舍 |
| DCPM / MRMS | 状态机 + supersede 链，**不物理删除** | supersede 会因把瞬时状态误判为稳定修订而过度触发 |

**注意 ActiveGraph 的自我限定**：它是一篇系统架构论文，
明确声明**不报告任务性能提升**，且确定性重放需要"行为体不得读取随机的墙钟/UUID"这一契约
（且该契约**只能动态检查**，违规在重放时才暴露）。

## 8. 对 Alaya 的启示（外部输入，待决策）

> 以下每一条都是**候选决策**，不是已确定的 Alaya 设计。采纳前应各自开一条
> "是否采纳 / 采纳到什么程度 / 落在哪个文档"的记录。

### C1 · "检索"这个隐喻本身可能是错的

最大的一批失败发生在**检索成功之后**：证据可达但未被使用，频率约为证据不可达的 10 倍（MemTrace）；
给出干净完整的 transcript 仍有 0.50 的忽略率（MERIT）；Fidelity 与 IEU 落差最大 76pp（StreamMemBench）。

**对 Alaya**：`05-inference.md` 的"检索与注入"若只描述"如何召回"，会漏掉真正的瓶颈。
需要显式设计**证据如何呈现给生成器**——时间戳、recency 标记、冲突可见性、provenance。
MERIT 观察到的两个具体失效模式值得记录：
① "stale 与 fresh 值并置而无时间戳或 recency 信号，agent 取平均、询问或挑旧的"；
② "多事实组合时 agent 只对最接近任务措辞的那个子集行动"。

### C2 · 表示粒度匹配优先于表示结构选择

图/扁平/层级的受控对比结论是"取决于配置"（UnifiedMem），且**粒度错配时结构反而有害**。
层级的上层收益是"窄而尖"的：DCPM 的跨域 core schema 只占节点 **1.3%，却承担约 4.1 个消融点**。

**对 Alaya**：`02-world-model.md` 与 `05-inference.md` 涉及世界内表示与蒸馏金字塔，
需要一条**粒度匹配原则**（表示粒度应匹配查询类型），而非"越结构化越好"的默认假设。
层级拆分阈值的方向性证据是明确的：**偏细安全、偏粗代价大**（−1.7 vs −6.3）。

### C3 · "不可变 + 可重建"必须搭配"重放成本边界"

ActiveGraph 提供了与 Alaya 最接近的架构验证，但它自己承认
**重放成本随日志长度增长、长寿命运行最终需要 checkpoint/compaction，而它尚未提供**。
Stanford 实测补上另一半：agentic 系统的构造 token 成本随 store **超线性**增长。

**对 Alaya**：`04-storage.md` 目前描述"基岩不可变、派生层可重建"，
但**没有给出基岩自身的增长与重放成本边界**。这是一个明确的缺口——
要么给出 checkpoint/compaction 设计，要么明确声明这是 M1 的已知限制并给出触发条件。

### C4 · 信念更新是与检索并列的一等能力

HorizonBench 的证据（缩短历史反而扩大 gap）说明**状态跟踪不是长上下文的副产品**；
DCPM 的证据（穿过 supersedes 指针是答对的关键预测因子，78% vs 31%）说明
**修订链是可用工程手段**，且它可以用零 LLM 的确定性读路径实现。

**对 Alaya**：`03-facts-and-consensus.md` 的"声称只追加、supersedes 不删"与这条证据同向，
是**被外部验证的选择**。可考虑补充的是：这条链在**检索时如何被显式暴露给生成器**
（而非仅在存储层保留），以及"检索到的是最新值还是全部历史值"的策略选择。

### C5 · 遗忘必须被设计，且其代价应当被显式定价

三组独立数字：1 年 TTL 的遗忘代价约 **5.9pp**，而索引维护只占 1.45pp（Opal）；
无遗忘的保留会**放大不一致**且惩罚随时间长而上升（Memora）；
**所有主流系统默认都不遗忘**（Stanford 实测）。

**对 Alaya**：与 `04-storage.md` 的保留策略、`03-facts-and-consensus.md` 的"可超越不可抹除"直接相关。
外部证据支持"标记失效而非物理删除"，但**不解决"被撤销的事实仍会影响下游摘要与缓存"**
这一传播问题（Mi-Memory 明确列为未解决）。Alaya 若声称"派生层可重建"，
需要回答重建是否足以覆盖撤销传播。

### C6 · 成本预算必须是一等公民

47× 的每正确答案能耗跨度、超线性的构造成本斜率、
以及 52 个系统中**只有 21% 报告任何效率指标**。
Harness 的设计规则（trade read breadth for write depth）本质上是**成本再分配**。

**对 Alaya**：`05-inference.md` 的蒸馏调度需要显式的**成本预算条款**，
且"构造侧超线性增长"应当作为一条需要监控的失效信号（而非仅容量问题）。

### C7 · 评测必须能区分"记忆管线四阶段"

九条方法论共识（§6）中，与 Alaya 现有 `07-evaluation.md` 最相关的是
第 1、2、4、6 条：测量单元、四阶段分解、防泄漏对照、多种子。
特别是 **leak check 必须作用于世界状态而非仅 prompt**——
MERIT 报告其两个防线（leak check、delta scoring）都是**在早期运行失败后才加入的**。

**对 Alaya**：`07-evaluation.md` 已有"离线回放验收"的方向，
但需要补充：**同一事实在多个条件下的重复探测**（而非行级聚合）、
**证据可达性与可用性的分离指标**、以及**明确的无记忆地板对照**。

### C8 · 弃答能力是一条独立的能力线，可能被增强手段损害

Engrama（图，唯一超过 full-context）在 adversarial abstention 上
**劣于** Mem0 与 full-context。这是"增强检索反而损害诚实性"的直接证据。

**对 Alaya**：`03-facts-and-consensus.md` 的事实裁决机有"降级为存疑"的机制，
这与弃答能力同向。外部证据提示：**该机制可能被"更强的召回"削弱**，
因此"存疑/弃答"应当在评测中被作为独立指标跟踪，而非仅看准确率。
