# 13 · 实测：导入路径的取舍

2026-09-14。以 `~/workspace-box/MEMORY.md`（4,824 字节）为样本，实测两条导入路径：
LLM 逐节抽取（`alaya import`）与会话中的 AI 直接经 MCP 写入。

**结论：移除 LLM 抽取路径**——`alaya import` 与 `llm`、`markdown` 两个包已删除。
原文入基岩后本就可检索；抽取唯一的独有能力是「当前值判定」，而它只对会演化的标量
属性有意义，这类属性在个人记忆里是少数，且更适合显式声称（`alaya claim`）。

---

## 一、LLM 逐节抽取（已移除）

### 1. 体积：膨胀 12.2 倍

| | 字节 | 相对源文件 |
|---|---|---|
| 源文件 MEMORY.md | 4,824 | 1× |
| `~/.alaya/events.jsonl` | 59,037 | 12.2× |
| └ 原文 10 条（`predicate=content`） | 11,331 | 2.3× |
| └ 断言 74 条 | 47,691 | 9.9× |

单条断言 645 字节，其中 `object` 只有约 40 字节——**94% 是哈希链与元数据**：

```json
{"v":1,"id":"sha256:ee1d…(71)","link":"sha256:d296…(71)","prev":"sha256:7166…(71)",
 "seq":11,"kind":"doc_fact","world":"world:real","scope":"user:garden",
 "subject":"urn:alaya:person:user:garden","predicate":"lives_in",
 "object":"广东惠州惠阳翡翠山（3期20栋）",
 "observed_at":"…","recorded_at":"…",
 "attributed_by":"urn:alaya:source:file:/Users/…/MEMORY.md",
 "note":"Core Memory/👤 核心画像 (User Profile)"}
```

### 2. 不是没压缩，是展开加损耗

原文一段（266 字）：

> **哲学/理论领域**：深度关注心灵哲学、人工智能伦理与安全、计算机科学理论、逻辑学。
> 乐于探讨意识本质、因果关系及人类未来。

抽成 7 条断言后合计 **313 字**——比原文更长，信息更少：

| 原文 | 断言 | 损失 |
|---|---|---|
| 深度关注 X | `interested_in X` | 「深度」降级为中性「感兴趣」 |
| 乐于探讨意识本质 | `enjoys 探讨意识本质` | 「探讨 X」被读成享受的对象；「意识本质」是概念而非活动 |
| （分类上下文） | 无 | 「哲学/理论领域」这层归类丢失 |

### 3. 碎片在检索上压制原文

`alaya search "心灵哲学"`：

```
1. interested_in 心灵哲学                        相关度 12.448
2. ...#精神与兴趣世界 content（整段原文）          相关度  5.334
```

BM25 天然偏袒短文档，**碎片以 2.3 倍压过整段原文**。空间没省下，上下文反而丢了。

### 4. 抽取对「检索」不是必需的

`alaya search "怕冷"` 与 `"Foveon"` 都命中了原文记录（相关度 2.06 / 2.02）。
原文入基岩后本就可检索。

抽取独有的能力只有一项：**当前值判定**（同一属性谁最新、何时被取代）。

### 5. 集合属性被误当成标量

`predicateRules` 要求「同一主体在同一属性上只有一个当前值」，实际抽出：

| 谓词 | 条数 |
|---|---|
| `enjoys` | 6 |
| `interested_in` | 4 |
| `proficient_in` | 3 |

这些**全部同时是当前值**，永远不会互相 supersede。谓词的基数本身就证明它不是标量属性——
对集合做当前值判定是范畴错误。

### 6. 两个实现缺陷

- **`is` 不该出现在推荐谓词表里**。实际抽出 `is | 极端怕冷`。`is` 能装下任何东西，
  任意两条 `is` 断言都会被判定为同一属性的新旧值，会**伪造 supersede 链**。
- **谓词分叉**：`camera` / `camera_foveon` / `camera_dji` 三条并存，
  正是 `predicateRules` 想避免的情况。

两条都随该路径一并移除而消失。

## 二、会话 AI 经 MCP 直接写入

库清空后，改由会话中的 AI 读整份文档、经 MCP 工具写入。仍是 32 条断言。

### 7. 体积 4.3×，内容首次真正压缩

| | LLM 逐节抽取 | AI 经 MCP |
|---|---|---|
| 条数 | 74 | 32 |
| 库体积 | 12.2× | **4.3×** |
| **`object` 总字节** | 47,691（9.9×） | **3,195（0.66×）** |

上下文不再被切碎：

- **投资框架**：LLM 抽成 8 条碎片（`asymmetry_priority` / `falsifiability_rule` /
  `probability_weighting_rule` / `market_stance` / `competence_circle` / `discipline_rule` /
  `survivalism` / `accepts_risk`），AI 写为 1 条，完整保留 8 条框架
- **相机**：`camera` / `camera_foveon` / `camera_dji` 分叉 → `owns_camera` 统一
- **`observed_at`**：从「全是文件 mtime」变为真实语义时间（2026-08-04 等 4 个）

原因是结构性的：会话 AI 读过整份文档，能判断「这 8 条是**一个框架**」而不是 8 个
独立属性；逐节抽取时模型每次只看到一节，做不到这一点。

### 8. 但三个问题与抽取无关

#### a) 存储格式吃掉 84%

```
object 总计:   3,195 字节
元数据+转义:  17,421 字节  ← 84%
其中三个哈希:    213 字符/条
```

一条 100 字节的断言要付 545 字节的账。**即使把 object 压到 0，也只省 15%**——
抽取已不是杠杆。

#### b) 中文检索基本不可达

```
「相机」0   「摄影」0   「摄像」0   「居住」0
「设备」0   「电脑」0   「手机」0   「车」0
「折叠」1   「哪吒」1
```

两个**独立**原因：

- **语义搬进了英文谓词名**。`owns_camera` 的 object 里没有「相机」两字。索引拼的是
  Subject + Predicate + Object + Note（`search/search.go`），所以谓词若写成中文
  「拥有相机」，搜「相机」即可命中
- **单字查询必然零命中**。bigram 至少需要 2 字：搜「车」得 0，而同一条记录搜
  「折叠」得 1。中文里搜单字很自然，这个缺口是真的

#### c) 并列事实被判定成历史

`owns_camera` 的 4 条：

```
seq=21  Sony A7R4A   → [历史]
seq=22  Foveon X3    → [历史]
seq=23  DJI          → [历史]（被 seq=32 取代）
seq=32  三台合并      → [当前]
```

写入者先分 3 条写（**正确**——三台相机并列存在），又写了一条合并版并声明 supersede。
结果库里说「用户曾经有 Sony A7R4A，现在没有了」——**这是假的**。

**不是写入者的错**：`owns_camera` 天然多值（一个人可以有多台相机、多个兴趣、多个设备），
机制却假设同一谓词只有一个当前值。写入者回头写合并版，正是被这个假设逼的。

## 三、结论

### 9. 决策

移除 `alaya import` 及 `llm`、`markdown` 包。原文入库与检索保留——它本就可检索；
结构化断言改由显式路径产生（`alaya claim` / MCP `memory_claim`），
由有全局视野的一方判断该不该抽。

判据：**这条会变吗？变了之后我需要知道什么时候变的吗？**
不会变、或本身是集合/叙述/带理由的，留在原文。

### 10. 遗留问题

按性价比排序：

1. **谓词用中文**（约定，零代码）——收益最大成本最低，直接解决 8b 的一半
2. **单字查询支持子串扫描**（`search/search.go`，约 20 行）——中文单字不该零命中
3. **多值属性显式建模**——需要设计决策；`owns_camera` 这类得有办法表达「并列有效」

### 11. 自省：已知有损的操作被默认化了

`writeClaims` 的注释写着「抽取必然压缩掉表格行标签、限定语与上下文，且丢得静默。
留下原文让这些损耗可逆」——写这句时已经知道有损，但应对是「留个备份」，
而不是质疑「那还抽它干嘛」。等到量化出来，代价是 12.2 倍的体积和一批排到原文前面的碎片。
