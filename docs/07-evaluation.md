# 07 · 评估与失效条件

设计的价值只能用对照实验证明。本章给出指标、实验方法、以及"何时承认这套设计该被推翻"。

## 1. 评估维度与指标

### 1.1 记忆质量

| 维度 | 指标 | 测法 |
|---|---|---|
| 检索质量 | recall@k 命中率、注入利用率（注入条目中被实际引用的比例） | 日志埋点 + 抽样人工评 |
| 忠实性 | 事实改写率（supersede 链中被推翻的比例应低且可解释） | 审计抽查 |
| 一致性 | 跨周同问题回答一致性、错误复发率 | 画像/场景评测集 |
| 卫生 | 声称重复率、陈旧率（N 天后被引用 vs 从未引用）、写入/检索比 | 管道统计 |

### 1.2 效率（单次）

- 同任务平均 token 消耗、往返轮数、重复提问率——**A/B：记忆开 vs 关**。

### 1.3 长期（跨会话）

- 任务成功率增量（有记忆 vs 无记忆，跨周跨月）；
- 项目/关系连续性（进行中事项是否零提示衔接）；
- 用户主观：被理解感、减少重复陈述感（问卷/行为信号）。

### 1.4 推理质量（本系统特有）

- 裁决准确率：裁决升级为 world_fact 后，被后续证据推翻的比例；
- 共识收敛速度与质量：冲突→结论的平均轮次、异议是否完整保留；
- canon 冲突检测率：注入虚构世界测试集，检测器命中率与误报率；
- 跨世界投影准确率：结构映射被用户/权威确认的比例。

## 2. 实验方法

1. **从第一天留 A/B 开关**：同一 Agent，`memory=off | memory=on | memory=on+recall`；
2. **评测集分层**：factual（查事实）、continuity（跨会话衔接）、efficiency（少问少 token）、fiction（虚构世界记忆与 canon 一致性）、multi-agent（scope 共识）；
3. **金标准 vs 反馈**：可自动判定的用金标准；主观的（意义理解）用行为信号 + 定期人工复核；
4. **追踪裁决得分卡**：每个"错了"的裁决必须有可解释的得分卡可供复盘——错误本身进基岩，成为修正原料。

## 3. 时间压力测试（设计自检）

定期用未来场景攻击设计：

| 场景 | 攻击 | 存活推演 |
|---|---|---|
| 10M 上下文 + 近零推理成本 | 还要记忆？全塞 context | 窗口解决"装得下"不解决"找得到/时效/矛盾"；注入层收缩、裁决/共识重要性上升 |
| 模型原生具备跨会话状态 | 外存多余 | 降级为审计/合规/可携带层；裁决机并入模型，基岩仍保忠实 |
| 记忆格式被标准化 | 自研白做 | 真源是可读格式 + adapter 层，迁移≈周末工作量 |
| 多智能体自治集群 | 记忆单位变了 | episodic 来源定义扩展；语义/共识/world 模型基本不动 |

**结论**：设计把赌注押在慢变量（文本/时间/因果/scope 共识）而非快变量（embedding/框架/上下文窗口）上。技术换代 = 换 adapter，不换内核。

## 4. 失效条件（何时承认该推翻）

设计者须诚实写下"此设计死亡"的条件：

1. **出现事实正确性与推理一体化的新范式**（模型原生跨会话状态，外存完全冗余）→ 核心退化为审计层；
2. **监管要求短生命周期存储成为主路径** → "基岩永存"不变式让位，系统改为记忆-遗忘循环主导；
3. **共识机被证明不可扩展或不可信**（群体规模下被操纵、Sybil、共识质量塌方）→ 需要全新的社会性事实机制；
4. **蒸馏质量无法随模型升级而单调改善**（旧模型错误被永久固化且无法重蒸馏清除）→ 基岩不灭的价值主张失效；
5. **在真实任务上，加记忆的系统长期跑不过不加记忆的强基线**（A/B 持续为负）→ 设计对问题域误判。

## 5. 不变式清单（任何优化不得违反）

1. **基岩永不丢**（原始证据是可重蒸馏的原料；唯一不可逆损失是删除它）；
2. **单事实源人类可读**（可 diff、可导出；任何私有格式只是派生物）；
3. **语义模型与技术栈解耦**（schema 不允许假设"今天的模型"存在）；
4. **更新不物理删除，supersedes 留时间线**（审计 + 纠错原料）；
5. **一切改变由评估驱动**（无 A/B 支撑的"改进"不允许动核心路径）；
6. **异议与共识同存**（删除异议 = 删除记忆的免疫系统）。

## 6. 里程碑路线图

| 阶段 | 目标 | 验证 |
|---|---|---|
| M1 单人降维 | 单用户单仓库：基岩 + 声称 + 基础裁决 + recall | 上述 1.1/1.2 指标起效 |
| M2 scope 化 | 用户×助手 dyad 共识、虚构世界容器（一部动漫/一个代码库） | 1.4 共识与 canon 指标 |
| M3 分布式 | 内容寻址副本、多 scope 收敛 | 一致性/可携带/遗忘验证 |
| M4 文明级 | 范式与评估固化 | 时间压力测试逐年复跑 |

**验证降维实例的试金石**：把 Alaya 接在一个真实个人助手 + 一个真实代码库上，跑"同一用户两月后回来，是否零提示续上上下文"——这是"人格同一性"最朴素、也最不可伪造的测试。
