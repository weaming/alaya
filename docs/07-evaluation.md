# 07 · 评估与失效条件

设计的价值只能用对照实验证明。本章给出指标、实验方法、以及"何时承认这套设计该被推翻"。

## 1. 评估维度与指标

### 1.1 记忆质量

**按管线四阶段分解，每阶段独立测量。** 外部调研的一致结论是：最终答案准确率会
混淆异质失败原因，且能出现"答案对但记忆状态错"的情况
（[12 §6](12-academic-evidence-on-agent-memory.md)）。

| 阶段 | 指标 | 说明 |
|---|---|---|
| ① 写入 | 记录完整率、抽取遗漏率、抽取污染率 | 是否忠实记录了输入 |
| ② 取出 | recall@k、证据可达率 | 该出现的证据是否出现 |
| ③ 使用 | **利用率**（注入条目中被实际引用的比例）、忽略率 | 可达的证据是否被用上 |
| ④ 用对 | **适用性正确率**（选中 `operative` 而非 `dormant` 的比例） | 用的是否是当前值 |

**为什么必须拆开**：外部实测中，失败探针里只有约 7% 是"取不到"，
约 73% 是"取到了但没用上"——两类解法完全不同（前者改检索，后者改呈现）。
不拆开时，"检索质量"这个指标会掩盖真正的瓶颈。

**弃答准确率是独立指标，不与准确率合并**：应弃答时的弃答率 + 不应弃答时的误弃率。
外部证据显示增强检索会显著损害弃答能力（某图系统 0.80 vs 扁平 1.00），
并入准确率后这一项会被平均掉。

**其余质量维度**：

| 维度 | 指标 | 测法 |
|---|---|---|
| 忠实性 | 事实改写率（supersede 链中被推翻的比例应低且可解释） | 审计抽查 |
| 一致性 | 跨周同问题回答一致性、错误复发率 | 画像/场景评测集 |
| 卫生 | 声称重复率、陈旧率（N 天后被引用 vs 从未引用）、写入/检索比 | 管道统计 |

### 1.2 效率与成本

外部实测的跨度说明这项不能省：不同架构的**每正确答案能耗相差 47 倍以上**（4.1 kJ ~ 186 kJ），
构造侧能耗可超过 300 次查询的总和；而 52 个记忆系统里**只有 21% 报告任何效率指标**，
管理成本与压缩比**无人报告**（[12 §5](12-academic-evidence-on-agent-memory.md)）。

| 维度 | 指标 |
|---|---|
| 单次 | 同任务平均 token、往返轮数、重复提问率（**A/B：记忆开 vs 关**） |
| 构造侧 | 每批事件的蒸馏 token / 调用数 / 墙钟；索引构建时间 |
| 管理侧 | 去重、更新、冲突消解的开销（外部系统普遍不报此项，需自建） |
| 存储 | footprint、压缩比（存储 token / 输入 token） |
| 延迟 | 查询 p50/p95、构造 p50/p95 |
| **斜率** | 每单位新增事件的蒸馏成本——**监控其趋势，而非只看总量**（见 §4 第 6 条） |

### 1.3 长期（跨会话）

- 任务成功率增量（有记忆 vs 无记忆，跨周跨月）；
- 项目/关系连续性（进行中事项是否零提示衔接）；
- 用户主观：被理解感、减少重复陈述感（问卷/行为信号）。

### 1.4 推理质量（本系统特有）

- 裁决准确率：裁决升级为 world_fact 后，被后续证据推翻的比例；
- 共识收敛速度与质量：冲突→结论的平均轮次、异议是否完整保留；
- canon 冲突检测率：注入虚构世界测试集，检测器命中率与误报率；
- 跨世界投影准确率：结构映射被用户/权威确认的比例。

### 1.5 状态推断质量（本系统特有）

对应 05 §5.4 与 03 §2.3。这是**最容易被"正确的检索"掩盖**的一类失效：
检索命中率可以完全正常，而系统稳定地返回过时值。

| 指标 | 测法 |
|---|---|
| `dormant` 识别率 | 构造"旧值被条件化"的场景，测系统是否选中 `operative` 值 |
| 推断正确率 | 构造"值从未被陈述、须由事件推断"的场景（HorizonBench 范式） |
| **检索/信念分离度** | 同时报告"检索命中率"与"当前值正确率"——**两者背离正是本项要捕捉的信号** |
| 弃答正确率 | 无法推断时是否输出 `unknown`，而非用默认值或最近值填充 |

**外部基线参考**：25 个前沿模型在这类任务上最好的只有 52.8%（人类 56–64%），
且把历史从 6 个月缩短到 0–14 天，差距**反而扩大**——说明这不是上下文长度问题
（[12 §4.1](12-academic-evidence-on-agent-memory.md)）。

## 2. 实验方法

1. **从第一天留 A/B 开关**：同一 Agent，`memory=off | memory=on | memory=on+recall`；
2. **评测集分层**：factual（查事实）、continuity（跨会话衔接）、efficiency（少问少 token）、fiction（虚构世界记忆与 canon 一致性）、multi-agent（scope 共识）；
3. **金标准 vs 反馈**：可自动判定的用金标准；主观的（意义理解）用行为信号 + 定期人工复核；
4. **追踪裁决得分卡**：每个"错了"的裁决必须有可解释的得分卡可供复盘——错误本身进基岩，成为修正原料；
5. **离线回放 harness（M1 完成定义的前提）**：M1 唯一可证伪验收点"用户两月后零提示续上上下文"在 M1 期间无法判定完成，会把不变式⑤架空。因此验收前移——用已有历史会话（聊天/提交记录）按时间切片构造回放集 + gold label，每次改动跑离线回放；"两月后"只作上线后的持续观测，不作 M1 完成门槛。

**以下六条是对上述方法的硬性补充**，来自外部调研中反复出现的评测事故
（[12 §6](12-academic-evidence-on-agent-memory.md)）：

6. **无记忆地板**：每次评测必须包含"同一模板 + 空记忆"的对照条件。
   没有地板时无法区分"记忆带来的增益"与"脚手架本身的增益"；
   更要紧的是——外部实测中出现过**无记忆基线达到 99.9%** 的情形，
   此时全部记忆指标实际不可测。
7. **防泄漏（leak check）必须作用于世界状态，而非仅 prompt**：
   断言 gold 值不出现在探测轮的输入与初始世界状态中。
   外部实践中这条防线是**在早期运行失败后才补上的**，不是一开始就有的——
   因此不能假定它自然成立。
8. **测量单元是"知识点"而非"问题行"**：同一事实应在多个受控条件下重复探测
   （记忆年龄 × 问题类型 × 证据条件）。行级聚合会把探测同一事实的多个问题当作独立项，
   从而**无法固定事实、变化条件**，也就无法归因。
9. **多种子 + 多 backbone + 统计检验**：外部实测中，同一系统同一条件的多种子差异最大达 **0.45**，
   跨模型跨度 0.30–0.95——**单次运行的结果不可作为结论**。
   报告须含配对检验与置信区间，而非点估计。
10. **judge 可靠性必须被审计**：LLM-as-judge 的结论须与人工标注对照
    （外部实践中报告的一致率为 88.3% ~ κ=0.98 不等），并**说明不一致的方向**
    （哪一侧被高估或低估），因为方向决定了指标是上界还是下界。
11. **harness 与 gold label 纳入版本控制**：外部有过同一系统因评测脚本与参数差异
    而结果相差近 10 倍（7.66% → 61% → 宣称 83%）的先例。
    因此回放集、切片规则、gold label、复现命令必须与代码一同版本化，且可被第三方复跑。

## 3. 时间压力测试（设计自检）

定期用未来场景攻击设计：

| 场景 | 攻击 | 存活推演 |
|---|---|---|
| 10M 上下文 + 近零推理成本 | 还要记忆？全塞 context | 窗口解决"装得下"不解决"找得到/时效/矛盾"；注入层收缩、裁决/共识重要性上升 |
| 模型原生具备跨会话状态 | 外存多余 | 降级为审计/合规/可携带层；裁决机并入模型，基岩仍保忠实 |
| 记忆格式被标准化 | 自研白做 | 真源是可读格式 + adapter 层，迁移≈周末工作量 |
| 多智能体自治集群 | 记忆单位变了 | episodic 来源定义扩展；语义/共识/world 模型基本不动 |

**结论**：设计把赌注押在慢变量（文本/时间/因果/scope 共识）而非快变量（embedding/框架/上下文窗口）上。技术换代 = 换 adapter，不换内核。

## 4. 失效条件（何时承认该推翻）

设计者须诚实写下"此设计死亡"的条件：

1. **出现事实正确性与推理一体化的新范式**（模型原生跨会话状态，外存完全冗余）→ 核心退化为审计层；
2. **监管要求短生命周期存储成为主路径** → "基岩永存"不变式让位，系统改为记忆-遗忘循环主导；
3. **共识机被证明不可扩展或不可信**（群体规模下被操纵、Sybil、共识质量塌方）→ 需要全新的社会性事实机制；
4. **蒸馏质量无法随模型升级而单调改善**（旧模型错误被永久固化且无法重蒸馏清除）→ 基岩不灭的价值主张失效；
5. **在真实任务上，加记忆的系统长期跑不过不加记忆的强基线**（A/B 持续为负）→ 设计对问题域误判。
6. **构造侧成本斜率持续上升且无法用快照/增量重放平抑** → 外部实测中已有系统在
   256K tokens 后急剧发散（"长期成本由算法增长斜率决定"）。若 Alaya 的重放与蒸馏
   同样超线性，则"基岩永存"在工程上不可维持，不变式①需要重新表述。

## 5. 不变式清单（任何优化不得违反）

1. **基岩永不丢**（原始证据是可重蒸馏的原料；唯一不可逆损失是删除它）；
2. **单事实源人类可读**（可 diff、可导出；任何私有格式只是派生物）；
3. **语义模型与技术栈解耦**（schema 不允许假设"今天的模型"存在）；
4. **更新不物理删除，supersedes 留时间线**（审计 + 纠错原料）；
5. **一切改变由评估驱动**（无 A/B 支撑的"改进"不允许动核心路径）；
6. **异议与共识同存**（删除异议 = 删除记忆的免疫系统）。

## 6. 里程碑路线图

| 阶段 | 目标 | 验证 |
|---|---|---|
| M1 单人降维 | 单用户单仓库：基岩 + 声称 + 基础裁决 + recall | 上述 1.1/1.2 指标起效 |
| M2 scope 化 | 用户×助手 dyad 共识、虚构世界容器（一部动漫/一个代码库） | 1.4 共识与 canon 指标 |
| M3 分布式 | 内容寻址副本、多 scope 收敛 | 一致性/可携带/遗忘验证 |
| M4 文明级 | 范式与评估固化 | 时间压力测试逐年复跑 |

**验证降维实例的试金石**：把 Alaya 接在一个真实个人助手 + 一个真实代码库上，跑"同一用户两月后回来，是否零提示续上上下文"——这是"人格同一性"最朴素、也最不可伪造的测试。
